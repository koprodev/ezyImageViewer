# ezyImageViewer 사용자 가이드

이 문서는 현재 정상 제품 UI에서 사용할 수 있는 기능과 제한을 설명합니다. 내부
진단 명령이나 아직 제품 게이트를 통과하지 않은 코덱은 지원 기능으로 간주하지
않습니다.

## 설치

지원 범위는 Windows 10 build 19041 이상 x64입니다. 일반 설치 파일은 시작할 때
`현재 사용자` 또는 `모든 사용자`를 선택하며 기본값은 현재 사용자입니다. 모든 사용자
설치는 Windows 관리자 승인이 필요합니다.

- 시작 메뉴 바로가기는 기본으로 만듭니다.
- 바탕 화면 바로가기는 기본으로 꺼져 있고, 지원 이미지 형식은 연결 프로그램 후보로 기본 등록합니다.
- 이미지 형식 등록은 Windows의 현재 기본 앱을 강제로 바꾸지 않습니다.
- 제거할 때 프로그램과 installer가 만든 바로가기·등록 정보는 삭제하지만, 설정·최근 파일·
  로그·복구 자료가 있는 `%LOCALAPPDATA%\ezyImageViewer`는 기본으로 유지합니다.
- 같은 이름의 이전 packaged MSIX가 설치돼 있으면 새 installer가 이를 자동 제거하지 않습니다.
  필요한 작업을 먼저 내보낸 뒤 Windows 설정에서 이전 앱을 제거하고 다시 설치해야 합니다.

정식 서명 후보의 clean VM 설치·업그레이드·제거 검증은 아직 출시 전 gate입니다. 파일 이름에
`dev-unsigned`가 있는 공개 프리릴리스는 개인 평가·테스트용이며 일반 사용자용 정식판이 아닙니다.

### Installer + 단일 Portable 프리릴리스

`v1.0.36-preview.1`은 두 가지 실행 방식을 제공합니다. 설치 UI와 MIT 라이선스 안내는
Windows 표시 언어가 한국어이면 한국어를 사용하고, 그 밖의 환경에서는 영어를 기본값으로
사용합니다.

- Setup EXE: 현재 사용자/모든 사용자 설치, 시작 메뉴 및 선택적 바탕 화면·이미지 연결 등록
- 단일 Portable EXE: 설치와 레지스트리 등록 없이 실행하며 필요한 런타임을 사용자 임시
  폴더에 풀어 사용

두 파일 모두 unsigned이므로 실행 전 함께 게시된 `SHA256SUMS.txt`와 SHA-256을 대조해야 합니다.
Portable을 Windows 연결 프로그램으로 직접 선택했다면 EXE를 이동하거나 이름을 바꾸지 마세요.
Windows에 저장된 경로가 더 이상 유효하지 않게 됩니다.

### Basic Portable 프리릴리스

기존에 공개된 첫 바이너리는 설치 패키지가 아니라 unsigned 평가·테스트용 ZIP입니다.
ZIP 전체를 일반 로컬 폴더에 압축 해제하고 `ezyImageViewer.exe`를 실행합니다.
실행 전 함께 게시된 `SHA256SUMS.txt`와 ZIP의 SHA-256을 대조하세요. 코드 서명이 없어
Windows SmartScreen이 경고할 수 있습니다.

- package identity, 바로가기, 레지스트리, 파일 연결, 서비스는 설치하지 않습니다.
- 공식 Snipping Tool callback은 사용할 수 없고 기존 clipboard fallback만 사용합니다.
- 삭제는 앱을 닫고 압축 해제한 폴더를 지우면 됩니다.
- 설정·최근 파일·로그·복구 자료는 `%LOCALAPPDATA%\ezyImageViewer`에 남습니다.
- Windows App SDK WinUI Engineering Preview 조건 때문에 production 또는 live 운영용으로
  의존하지 말고 평가·테스트에만 사용합니다.

## 파일 열기와 포맷 지원

| 구분 | 확장자 | 현재 동작 |
|---|---|---|
| 지원 | `.jpg`, `.jpeg`, `.jfif`, `.png`, `.bmp`, `.dib`, `.rle`, `.gif`, `.tif`, `.tiff`, `.ico`, `.webp` | 정상 열기·폴더 탐색 대상입니다. |
| 지원 | `.svg`, `.svgz` | 보안 정적 모드로 렌더링합니다. |
| 조건부 지원 | `.avif`, `.heic`, `.heif`, `.hif` | 호환되는 Windows 시스템 WIC 코덱이 설치된 경우에만 열립니다. 앱이 코덱을 자동 설치하거나 내려받지 않습니다. |
| 프로젝트 | `.ezyimg` | 원본 배경과 편집 객체를 함께 저장한 ezyImageViewer 프로젝트를 엽니다. |
| 현재 미지원 | `.pdf`, `.psd` | 알려진 포맷이지만 정상 열기·파일 선택·폴더 탐색에서는 거부됩니다. |

표에 없는 포맷은 현재 지원하지 않습니다. 앱은 확장자만 믿지 않고 파일 시그니처를
먼저 확인합니다. 확장자와 실제 내용이 다르면 진단 경고를 표시하며, 다른 디코더로
추측해서 다시 해석하지 않습니다.

### 포맷별 제한

- GIF 애니메이션은 재생할 수 있습니다. 주석이나 변형을 시작하면 확인 후 현재
  프레임 한 장으로 평탄화되며 애니메이션 프레임은 복원되지 않습니다.
- 다중 페이지 TIFF와 ICO는 페이지 단위로 탐색합니다.
- SVG/SVGZ는 JavaScript, 외부 이미지·폰트·네트워크 리소스, DTD와 entity를
  차단합니다. 동적·외부 의존 콘텐츠는 원본과 다르게 보이거나 거부될 수 있습니다.
- `.ezyimg`는 원본 배경 바이트를 프로젝트 안에 포함합니다. 프로젝트를 공유하면
  편집 결과뿐 아니라 포함된 원본도 함께 공유됩니다.

### PDF와 PSD 격리 경계

PDF/PSD 렌더러는 보안·충실도 검증을 위한 별도 CodecHost 프로세스에만 존재합니다.
CodecHost 패키지를 설치해도 정상 UI의 PDF/PSD 지원이 켜지지 않으며, 이를 켜는 사용자
설정도 없습니다.

- 호스트는 요청마다 제한된 AppContainer에서 실행되고, 입력은 inline 데이터 또는
  읽기 전용 파일 handle로 받으며 원본 경로 문자열은 전달받지 않습니다.
- 시간·CPU·메모리·출력 크기 제한을 넘기거나 프로토콜 검증에 실패하면 호스트를
  종료하고 실패로 처리합니다. 주 앱 프로세스 안의 디코더로 우회하지 않습니다.
- 구현 범위는 PDF 페이지 래스터 표시와 PSD 합성 이미지 표시입니다. PDF 원본 객체
  편집이나 PSD 레이어 편집을 제공하지 않습니다.
- 외부 코퍼스, reference golden, 암호화·손상 파일, 실제 Photoshop 제작 파일의
  충실도와 물리 기기 검증이 끝나기 전에는 제품 지원 포맷으로 광고하지 않습니다.

## 크기와 보안 제한

기본 제품 제한은 다음과 같습니다.

- 입력 파일: 최대 512 MiB.
- 프레임·페이지: 최대 10,000개.
- 한 변: 최대 65,500 픽셀.
- 전체 픽셀: 최대 500,000,000 픽셀.
- 표시 메모리 예산: 창당 384 MiB. 이 예산을 넘는 합리적인 크기의 이미지는 축소
  미리보기로 열릴 수 있습니다.
- SVG/SVGZ: 압축 해제 후 최대 64 MiB, XML element 최대 100,000개.
- 클립보드·캡처 가져오기: payload 최대 64 MiB.

손상됐거나 제한을 넘는 파일은 열리지 않습니다. 메모리가 부족하면 한 번 축소
미리보기를 시도하고, 그래도 실패하면 오류를 표시합니다. 축소 미리보기 상태에서는
원본 전체 해상도가 필요한 일부 저장 동작을 사용할 수 없을 수 있습니다.

## 저장, 내보내기와 메타데이터

이미지 내보내기는 PNG, JPEG, WebP를 지원합니다. 편집 가능한 프로젝트는 `.ezyimg`로
저장할 수 있습니다.

- 이미지 내보내기는 보이는 배경과 주석을 한 장의 픽셀 이미지로 합칩니다.
- `Ctrl+C`는 편집 결과 전체를 투명도 포함 이미지로 클립보드에 복사합니다. 자르기
  도구의 검토 영역이 표시된 상태에서는 그 영역만 복사하며, 자르기는 적용되지 않고
  검토 상태가 그대로 유지됩니다.
- 메타데이터 유지의 기본값은 꺼짐이며, 이 경우 메타데이터를 내보내지 않습니다.
- 파일에서 연 문서에서 메타데이터 유지를 켜면 촬영 정보 allowlist만 다시 구성합니다.
  GPS, MakerNote, 카메라·렌즈 일련번호와 Unique ID, 자유 텍스트·작성자 정보, 편집 전
  thumbnail은 항상 제거합니다. 방향과 출력 치수는 내보낸 픽셀에 맞게 정규화합니다.
- 원본 메타데이터가 손상됐거나 지원 범위를 넘으면 이미지는 메타데이터 없이 저장되고
  상태 표시줄에서 이를 알립니다.
- 클립보드와 캡처에서 연 문서에는 원본 메타데이터 유지 옵션을 제공하지 않습니다.

## 캡처와 클립보드

기본 전역 캡처 단축키는 `Ctrl+Shift+E`입니다. 캡처 버튼이나 단축키는 Windows 캡처
도구를 열고 완료된 이미지를 가져옵니다.

- `클립보드 캡처 감시`는 최초 설치 시 켜져 있습니다. 켜져 있으면 앱이 실행되는 동안
  클립보드의 새 외부 이미지를 감지할 수 있습니다.
- 감시를 꺼도 사용자가 명시적으로 누른 `클립보드에서 문서 열기`와 캡처 동작은 필요한
  순간 클립보드 이미지를 읽습니다.
- 캡처와 클립보드 이미지는 사용자가 저장하기 전에는 일반 이미지 파일로 자동
  저장되지 않습니다. 다만 편집을 시작하면 아래의 로컬 복구 checkpoint에 이미지
  내용이 포함될 수 있습니다.
- 파일과 이미지 내용은 캡처 처리나 보기 목적으로 외부 서버에 업로드되지 않습니다.

## 설정

설정 창에서 다음 동작을 바꿀 수 있습니다.

| 설정 | 기본값 | 설명 |
|---|---|---|
| 테마 | 시스템 | 시스템·밝게·어둡게 중 선택합니다. |
| 다른 파일을 열 때 | 현재 창 재사용 | 현재 창에서 열거나 새 창에서 열도록 선택합니다. |
| 클립보드 캡처 감시 | 켜짐 | 수동 복사 이미지 감시를 켜거나 끕니다. |
| 최근 파일 기록 | 켜짐 | 정상적으로 연 파일의 전체 경로와 마지막 열기 시각을 로컬에 기록합니다. |
| 폴더 탐색에 하위 폴더 포함 | 꺼짐 | 이전·다음 파일 탐색 범위를 하위 폴더까지 넓힙니다. |
| 전역 캡처 단축키 | `Ctrl+Shift+E` | 하나 이상의 보조 키와 문자·숫자·기능 키를 선택합니다. 다른 앱이 선점한 조합은 저장되지 않습니다. |
| 앱 정보·업데이트 확인 | 수동 버튼 | 현재 버전을 표시하고, 사용자가 누른 경우에만 기본 브라우저로 최신 릴리스 페이지를 엽니다. |

설정 파일이 없으면 위 기본값을 사용합니다. 설정 파일이 손상됐거나 알 수 없는
스키마이면 클립보드 감시와 최근 파일 기록을 모두 끈 개인정보 보호 fallback으로 시작합니다.

## 개인정보와 로컬 데이터

앱은 원격 분석·사용 통계 수집·자동 버전 확인 네트워크 기능을 사용하지 않습니다.
`업데이트 확인`은 앱이 HTTP 요청을 보내는 기능이 아니라 사용자가 누른 때에만 OS 기본
브라우저에 고정 GitHub Releases 주소를 전달합니다. 앱 데이터는 앱이 인식하는
`%LOCALAPPDATA%\ezyImageViewer` 아래에 저장됩니다.
공개 정책 문구와 제3자 플랫폼 범위는 [개인정보 처리방침](privacy.md)을 함께 확인하세요.

| 로컬 데이터 | 포함 내용 | 정리 동작 |
|---|---|---|
| `settings.json` | 테마, 동작, 개인정보 옵션, 단축키와 도구 기본값 | 설정을 저장할 때 원자적으로 교체합니다. |
| `recent-files.json` | 최대 20개의 전체 파일 경로와 UTC 마지막 열기 시각 | 기록을 끄면 즉시 삭제를 시도합니다. 최근 파일 창의 `모두 지우기`는 설정을 끄지 않고 목록만 삭제합니다. 존재하지 않는 파일은 목록을 읽을 때 제거합니다. |
| `logs/ezy-*.jsonl` | 앱 버전·OS, 허용된 이벤트 이름, 오류 코드·예외 타입, 포맷·렌더러·경과 시간 | 기본 7일, 파일당 1 MiB, 최대 5파일을 유지하고 새 로그를 쓸 때 오래된 파일을 삭제합니다. |
| `recovery/*.recovery` | 수정 중인 문서의 원본 배경과 편집 상태를 담은 로컬 `.ezyimg` 형태 payload | 정상 저장·창 닫기·앱 종료 시 삭제합니다. 비정상 종료 시 다음 시작의 복구 선택까지 남습니다. |
| `recovery-quarantine/*` | 손상되거나 무결성 검증에 실패한 복구 파일 | 새 격리 항목을 처리할 때 기본 30일·최대 20파일·총 512 MiB 제한으로 정리합니다. |
| `crash-markers/*` | 복구 세션 식별자와 시작 UTC 시각 | 정상 세션 완료 시 삭제합니다. |
| `startup-health.json` | 같은 시작 오류인지 판별하는 SHA-256 fingerprint, 연속 횟수, UTC 시각 | 정상 시작·종료 후 삭제하며 오래된 기록은 기본 7일 뒤 무시합니다. |

### 로컬 로그

로그에는 문서 경로 원문, 예외 메시지, stack trace, 이미지 바이트를 기록하지 않습니다.
문서 경로가 필요한 이벤트는 실행할 때마다 새로 만든 임의 키로 HMAC-SHA-256 처리한
짧은 식별자만 저장하므로 다른 실행의 같은 경로와 연결되지 않습니다. 로그는 자동으로
외부 전송되지 않습니다.

### 작업 복구

수정된 문서는 마지막 변경 후 약 2초 동안 추가 변경이 없으면 창별 복구 checkpoint를
갱신합니다. checkpoint에는 원본 배경 바이트와 편집 객체가 포함될 수 있으며 SHA-256
무결성 검사를 하지만 별도로 암호화하지 않습니다. 민감한 이미지를 편집하는 PC에서는
Windows 계정과 저장 장치 보호를 함께 사용하세요.

비정상 종료 뒤에는 다음 선택을 제공합니다.

- `모두 복구`: 검증에 성공한 checkpoint를 창별로 엽니다. 복구된 작업은 안전한
  위치에 직접 저장해야 합니다.
- `모두 버리기`: 이전 세션의 checkpoint와 marker 삭제를 시도합니다.
- `나중에`: 이전 checkpoint를 유지해 다음 시작에서 다시 결정할 수 있게 합니다.

### 업데이트 확인

설정의 `앱 정보`에서 현재 버전을 확인할 수 있습니다. 사용자가 `업데이트 확인`을
누르면 기본 브라우저로 koprodev의 최신 GitHub Releases 페이지만 엽니다.

- 앱은 GitHub API를 호출하거나 최신 버전과 현재 버전을 비교하지 않습니다.
- 백그라운드 확인, 자동 다운로드, 자동 설치, 자동 재시작을 수행하지 않습니다.
- 릴리스 노트 확인과 Portable 또는 향후 설치 파일 다운로드·실행은 사용자가 브라우저에서 직접 수행합니다.

## 안전 모드

같은 시작 오류가 두 번 연속 감지되면 다음 시작에서 안전 모드를 제안합니다. 안전
모드는 저장된 설정을 바꾸지 않고 그 실행에서만 다음 기능을 끕니다.

- 클립보드 감시와 전역 캡처
- 최근 파일 표시·기록
- 하위 폴더 탐색
- 자동 복구 열기와 새 복구 checkpoint

안전 모드에서 열지 않은 이전 복구 데이터는 자동으로 버리지 않습니다.
